# Design

Archive Icons and the existing windowed filmstrip mount generic image placeholders. A shared near-viewport intersection observer queues missing derivatives; a second strict viewport observer prioritizes foreground jobs over near-viewport prefetch. Cached derivatives restore immediately without waiting for a running generation job. One job at a time loads a same-origin or local source, prefers an authored thumbnail when present, checks the actual selected source's budget (original metadata does not disqualify a distinct authored thumbnail; an alias of an original still uses its budget), sizes to a 96 / 192 / 288 pixel tier and encodes a JPEG asynchronously. Unsupported or failed sources retain their placeholder. Source dimensions that lack metadata can only be checked after the browser has acquired the image. The filmstrip can reuse the full-resolution viewer's already-requested image when the source matches.

The current-folder derivative cache holds at most 256 results and 4 MiB of encoded blobs; independently at most 100 image elements may be mounted, with a single running job. Identity includes project, file, URL, byte metadata and dimension tier. Mounted targets lease derivatives. Leaving the near-viewport window cancels obsolete queued/running work but retains the mounted image as an offscreen buffer. Re-entry touches both LRU orders without changing the image node. Under mount pressure, detach the least-recently-used offscreen image and restore its generic placeholder; retain its encoded derivative if cache capacity permits. Under entry/byte pressure, evict the least-recently-used derivative whose leases are all offscreen (or absent), detaching its users before revocation. Protect near-viewport leases; wait if no safe slot exists. A cached derivative can be remounted immediately, even during another image's encode. Cache hits and retained nodes do not trigger original decoding. Layout switches and other full renders discard obsolete targets but retain compatible derivatives within the same Archive view/folder. Changing the folder or logical view (e.g. Sources), leaving Archive or switching project identity clears both buffers and owned URLs. A new edit revision reconciles retained targets and cache entries with the owning project. Canceled jobs can requeue on rapid re-entry, and stale observer callbacks/async completions cannot mount into replacement targets. Viewer originals remain governed by the existing separate neighbor cache. These limits are founder-approved starting values, not measured browser memory budgets.

A compatible desktop pointer selection, including first selection from an empty selection, changes the affected detail rows, checkboxes and select-all state, then replaces and binds only the inspector. The compatibility check requires zero or one selected files, no selected folders, an expanded inspector and no active file/name edit. Composition changes, including bulk transitions, and other view operations use full rendering. Ordinary file-list full renders build only the active desktop/mobile presentation; a media-query change rebuilds once for the new presentation, restores compatible focus and retains canonical selection and scroll behavior. File editing/renaming deliberately retains both presentations to avoid replacing input drafts during resize. Image view owns its own resize. Toolbar fitting skips unchanged observed geometry and still remeasures on font readiness. Browser verification of the breakpoint path is pending.

The existing Diagnostics adapter receives thumbnail task outcomes and bounded cache/queue metrics, including optional last/max mountedPreviews (shared mounted derivative elements, attributed to the active/owning layout, not unique asset count or browser memory). Viewer decode and estimated viewer RGBA bytes remain independent. The upload audit found one legacy notification per successful imported file. The historical 159 aggregate invalidations cannot be reconstructed from that export alone.
