# Design

Pass a local map of project IDs to changed domains through nested writes that belong to one successful commit. The existing bootstrap dirty boundary advances the session revision once, then invalidates each provable owner through the existing coordinator. Unknown ownership takes the conservative fallback. No retained read that depends on changed fields should precede notification. The staged Note attachment check can verify the pending person directly when the warm index predates creation.

| Owner | Canonical writes and notification |
| --- | --- |
| Person edit and creation | People timestamps and fields, changed family records, new Places, actual photo changes and primary repairs, Archive attachments, Notes links and the first-person project default when applicable. Notify after event and reference reconstruction and before render. Staged unchanged photo attachments avoid replacing arrays or advancing photo timestamps. |
| Relationship connect, edit and unlink | Families and new Places when created. Complete event and evidence reconciliation at the successful write, before the view refresh. |
| Event reconstruction | Index people once for live and detached builds. Reuse equivalent event objects. Record added, replaced and removed event owners, including changes in other projects. Replace Archive and Notes records only where a stored event link is pruned. Report the owners of removed source links and retain the source-link collection identity when pruning removes nothing. Duplicate event identity and unowned links trigger fallback. |
| Notes body and collections | Notes only, with no Place dismissal pass. A Note source-link change or copy with source links adds sources. Only a Place link or a copy carrying Place links needs dismissal reconciliation. |
| Archive evidence | Classify source links by source and target owner. File-to-note writes include the reverse Note link. Validate the batch before writes, stage the notification, and restore affected objects and the source-link collection on failure. New Source creation with linking and bulk file-to-Place creation notify once after the batch. |
| Albums and image tagging | Media for favourites, upload, tag and region writes. Include People for primary photo, timestamp or repair writes. Repairs report the owning project for each affected person, including other projects. Archive image regions belong to Archive. Permanent photo cleanup keeps one conservative global notification because it scans cross-collection legacy references. |
| Place editor, merge and delete | Editor writes Places. Merge and delete report owner domains found while retargeting references, then incorporate derived effects. A changed generic legacy link has no typed read-model domain and uses fallback. |
| Geneograph transfer and Sync | Transfer touches the board. Sync Apply and history restore derive domains from before/after patch owners and the board. Failed Apply restores its patch journal. General canvas edits retain their existing notification path. |

The provider inputs and variants are listed in the [source map](../../../doc/source-map.md#shared-project-read-model). Notable remaining rebuilds include family indexes after a People change, media-dependent search and membership preparation after a favourite, and the People directory's conservative collection-identity variant when the global source-link array is replaced. That variant can rebuild the directory even when a typed source-link change belongs to another project.

Place dismissal expiry traverses authored references for projects with pending unlinked decisions. It collects matches only for those pending Place IDs and leaves unrelated decisions in place. Known non-reference edits skip this pass. The shell and direct Places render still check the active project for legacy paths. Unclassified commits still check across projects. Append-only activity behavior is outside this change.

Other conservative paths include permanent person and Archive deletions, import/replacement, general canvas/board operations, and remaining review-only and folder actions. Import continues to release retained state during staged activation and rollback. The performance runs in [tasks.md](tasks.md) do not attribute the earlier 3.9-second page-wide task.
