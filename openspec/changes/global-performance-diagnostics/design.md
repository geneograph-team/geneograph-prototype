# Design

`core/application-performance.js` owns an in-memory 256-operation rolling buffer and config; the Tree adapter drops the project argument. Start appends to the retained buffer with a new recording epoch; Stop marks retained pending traces stopped, Clear stops and discards all retained samples. Configuration changes only while stopped. Each sample identifies its recording epoch, module and mode; schema v2 adds those fields and current configuration, retains Tree detail fields in Detailed mode and omits them in Basic mode. Evicted and earlier-epoch traces cannot write. No wall-clock timestamp, exception text, user-supplied label, project or person identifier is exported. Export is explicit JSON download.

Initial operations: Projects activation, GEDCOM parse/map/commit (synchronous); destination-module navigation, application shell render, Projects startup/open render, People, Albums, Archive, Notes, Places and Publish main render, Geneograph home, board open and editor render, existing Tree asynchronous/layout/interaction traces, and hosted Places map initialization until load/failure/disposal. Nested operation durations overlap and must not be summed. Non-Tree Detailed currently has the same operation durations/outcomes as Basic; no fabricated internal counters. Further per-module stages belong to their performance tasks. Map initialization excludes offline unsupported-map fallback and later style changes. Disabled path skips trace creation; standalone module tests may omit recorder.

Diagnostics immediately precedes About. The topbar record icon is visible only while active and stops without clearing before opening Diagnostics. Scope and mode lock while active; no-project Projects recording is supported. Default entire application, Detailed (retains prior Tree detail). Clear stops. Manual browser QA remains pending.
