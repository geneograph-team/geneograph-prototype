## ADDED Requirements

### Requirement: Match missing place coordinates after confirmation

Following offline preparation, the importer SHALL automatically attempt at most 150 distinct eligible unresolved places per import, prioritized by linked records, after disclosure and confirmation. Matching SHALL run automatically after the main import with no pre-import settings block or opt-out checkbox. A concise disclosure beside the import action SHALL explain that place names may be sent to the existing providers. The validated offline draft SHALL commit and activate before any matching lookup. Start a session-local, project-scoped asynchronous job after commit, with a nonblocking status/stop action and provider attribution. Stopping lookup retains completed matches; closing the result report does not stop the job. Canceling or failing the main import before commit starts no job. Preserve authored names, existing coordinates, links and invalid/conflicting source evidence. Only unique strongly matched settlement candidates receive coordinates; uncertainty and historical or unsupported context remain unresolved. Final detached validation SHALL precede commit. Network failures SHALL NOT prevent import. Each later coordinate-only mutation SHALL recheck live project/job/record identity, unchanged input, missing coordinates and valid point; preserve manual edits and cancel on deletion/replacement. Limit concurrent import lookups globally to two, deduplicate in-flight queries, prioritize queued manual provider requests, and recheck cooldown at dispatch. Coalesce progressive Places list/review/count/marker/inspector updates without remounting the whole module or resetting viewport, search, selection or open drafts. Session jobs end on reload. Keep matching outcomes internally for diagnostics; omit the separate coordinate-matching statistics block in the result. Disclose actual quota or provider interruptions nonblockingly in the running status and using expandable warnings in the subsequent import report; ordinary uncertain or ineligible matches remain in Places Needs review. Retain provider attribution when lookups were attempted.

#### Scenario: Incomplete context and equivalent authored place names (#498)

- **WHEN** complete authored hierarchy strings differ only in case, canonical Unicode, insignificant whitespace or a demonstrably incidental final full stop, without conflicting/invalid coordinate evidence
- **THEN** consolidate before ranking even without recognized country; retain original fact text, compatible coordinates, aliases within the canonical uniqueness contract and all associations
- **AND** do not merge by locality-only similarity or reorder stored names.

A meaningful settlement-only or settlement-plus-region query SHALL be eligible without an explicit country. Recognize exact bounded multilingual regional aliases, reversed country/district-first hierarchy and explicit settlement-type prefixes. Match only exact normalized provider names or supported aliases, compatible country/administration and reliable type evidence; reject competing or truncated results, missing required metadata and weak confidence. Stronger evidence is required for incomplete context: provisional Geoapify overall/city-level thresholds .8 with country and admin, .9 with one, .95 for bare names (both scores and stable identity required for bare names). LocationIQ autocomplete has no documented equivalent score; do not assign a bare name on its response alone. Do not infer country from language or assume disputed sovereignty. Retain transient per-place reasons and provider outcomes in the in-memory import report, not visible summary, canonical records or telemetry. Existing request budget, provider fallback, authored names and source-coordinate protection remain unchanged.

Potentially inhabited candidates with missing or contradictory provider type/coordinate evidence SHALL remain available for ambiguity checks; a truncated primary response SHALL NOT authorize fallback or assignment. A country/region alias must be independently unambiguous; do not infer unsupported region translations.

#### Scenario: Session-local progressive matching (#499)

- **WHEN** the main GEDCOM import has committed successfully
- **THEN** the project is immediately available and up to two global import lookup slots enrich missing coordinates in the current browser session
- **AND** queued foreground search takes priority at the next provider dispatch; canceled jobs and queued work do not reserve future request slots
- **AND** successful point updates remain in their owning project, with stale/manual edits protected, and only changed Places rows/groups/markers and affected derived counts are refreshed in coalesced batches. Defer conflicting edits/menus; retain the map host/camera and active search controls. No persistence or server work.
