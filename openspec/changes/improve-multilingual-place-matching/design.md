# Design

Use exact normalized names, structured provider aliases, bounded transliteration and a country-qualified multilingual exonym table. Expand administrative abbreviations only for queries; compare named administrative types, stems and known ISO identifiers. A unique compatible candidate must still have valid coordinates and known country, with available score floor .60 and strongest-score thresholds .85 bare, .75 single context, .65 full context. Missing scores may be accepted with explicit context/type, reliable settlement metadata, identity and literal/alias match. Keep incomplete/conflicting competing candidates unresolved. No automatic provider retry; prefer configured Geoapify, or LocationIQ only when Geoapify is not configured. Manual search unchanged.

At job completion reconcile two unchanged newly enriched records only with shared provider identity, exact matching coordinates, compatible geography/type, no authored conflicts or dismissal. Use canonical merge and preserve selection/project ownership; more specific name wins. One-sided coordinate/name pairs are review suggestions, not proof. A verified merge invalidates its old snapshots; further multi-way merges are left for review. Diagnostics are session-local and explicit retry is a one-place job using existing scheduling. No data schema change. Numerical fixtures do not establish actual live provider behavior.
