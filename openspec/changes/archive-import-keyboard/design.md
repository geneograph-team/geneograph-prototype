# Design

## Staged import

A shared local progress panel is inserted below the modal header, outside scrolling preview content. Known work totals report completed processing (success plus failures); final linking/rendering is indeterminate. The live-region announcement is throttled; the body, rather than the progress panel, is marked busy. Existing beforeClose guards and disabled controls prevent duplicate submissions and ordinary dismissal. A render opportunity precedes expensive work, with a fallback timer for a hidden tab. Album preparation and shared photo preparation/commit are sequential; Archive preparation yields every 16 entries, and canonical import yields between files. Keep existing per-file mutation semantics and linking callbacks instead of batching record writes without measured evidence. Capture destination identity, revalidate before commits, preserve original bytes and retain failed staged items for retry. Ordinary idle removal/cancel remain unchanged.

Transient staging previews use the original File as their generation source, never a mounted original. Lightweight shells hydrate near the viewport, up to 32 mounted derivative images and 2 MiB encoded bytes per active session, a maximum 192-pixel edge and one running job globally. A 48 Mi-pixel source guard bounds supported generation dimensions after load. This is a presentation budget, not a browser memory guarantee. Unsupported/failed/oversized sources keep their generic icon. A session disposes its owned object URLs and rejects stale completions on re-render or modal removal. The canonical Archive buffer remains unchanged.

## Archive folder and keyboard

Create folder uses existing validation and record creation, closes the modal and renders the current location (no navigation history append or filter reset). One Archive-scoped keyboard handler dispatches unmodified arrows/Enter only from the file browsing workspace, focused row/tile or Image stage/strip; it ignores other modules, Sources, menus, dialogs, modified shortcuts and nested controls. Initial/return focus is established on the valid selected item or workspace, with explicit layout handoff. Existing selection, edit guards, viewer and folder-open paths own canonical changes. List order uses displayed rows; tile navigation chooses nearest adjacent visual row then nearest horizontal center, with horizontal movement restricted to the current row. The narrow mobile list presentation uses its actual list order, even if the desktop layout preference is Icons. No wrapping. Image Left/Right uses the existing index navigation. Retain compatible desktop rows and thumbnails; focus and scroll selected items. The Image viewer and canonical thumbnail cache are unchanged. Existing independent inputs and menus retain their keys. The design uses existing current-selection state rather than adding a persistent keyboard cursor.

## Verification limits

The connected repository environment can execute actual source assertions in isolated JavaScript with browser/Node module test doubles, not the native checkout or browser. No new browser performance timings, visual, direct-file or accessibility pass is claimed. Full modal interaction and upload responsiveness/paint, full keyboard/focus behavior, and before/after measurements remain acceptance work.
